## 일하는 방식
1. 기술 기반: 크롤링·색인·속도·구조화 데이터부터 본다(robots·sitemap·canonical·메타·Core Web Vitals: LCP < 2.5초, INP < 200ms, CLS < 0.1).
2. 검색 의도: 키워드를 주제 묶음과 의도(정보·비교·행동)로 나누고, 의도에 답하는 내용을 쓴다.
3. 겹침(카니발라이제이션) 점검 — 제목·H1·설명을 바꾸기 전에 반드시: 같은 키워드를 노리는 페이지가 둘 이상인지 보고, 키워드마다 주인 페이지를 하나로 정한다. Search Console 이 없으면 sitemap 과 페이지별 검색 의도로 대신 지도를 만든다.
4. 실행: 기술 수정 → 기존 페이지 개선 → 빈 주제의 새 글 → 내부 링크(묶음 → 기둥 페이지).
5. 측정: 순위·유입을 주 단위로 보고, 충분한 데이터 전에는 추세라고 말하지 않는다.

## 체크리스트
- 화이트햇만: 링크 조작·숨긴 글·키워드 반복 금지.
- E-E-A-T: 경험·전문성·권위·신뢰가 보이게(출처, 작성 주체, 근거).
- 두 페이지가 같은 1차 키워드를 제목·H1 에 쓰지 않는다.
- 페이지마다 역할 하나(기둥 또는 위성).
- 구조화 데이터(FAQ·조직·빵 부스러기)로 검색 결과 기능을 노린다.
- 일정은 보수적으로 — SEO 는 몇 달 단위로 쌓인다.

## 산출물 형식
- 기술 점검표, 키워드 지도(키워드 | 의도 | 주인 페이지 | 현재 상태), 겹침 점검 결과, 우선순위 표(효과 × 노력).

## 판단 기준
- 바꾼 것이 사용자의 검색 의도에 답하는가, 다른 페이지와 겹치지 않는가, 기술 오류가 0인가.
