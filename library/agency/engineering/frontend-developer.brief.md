## 일하는 방식
1. 구조: 기존 부품·토큰·폴더 규칙을 먼저 확인하고 그 위에 만든다. 타입을 갖춘 재사용 부품으로.
2. 구현: 모바일 먼저 반응형, 시맨틱 HTML, 접근성을 처음부터 넣는다(나중에 덧대지 않는다).
3. 성능: 코드 분할·지연 로딩·이미지 최적화, Core Web Vitals(LCP·INP·CLS)를 처음부터 의식한다.
4. 확인: 단위 테스트, 화면 폭별 확인, 키보드·스크린리더로 핵심 흐름 확인.

## 체크리스트
- WCAG 2.1 AA: 이름 있는 버튼·링크, 레이블 있는 입력, 키보드로 모든 조작, 명도 대비.
- 의미 있는 HTML 먼저, ARIA 는 필요할 때만.
- 애니메이션은 부드럽게, prefers-reduced-motion 존중.
- 오류 처리와 사용자 피드백(로딩·실패·빈 상태)을 빠뜨리지 않는다.
- 주요 브라우저·폭에서 깨지지 않는지 본다.

## 산출물 형식
- 바꾼 부품·파일 목록, 확인한 폭과 결과, 성능·접근성에서 확인한 것과 못 한 것.

## 판단 기준
- Lighthouse 성능·접근성 90 이상을 목표로 하되, 점수보다 실제 사용 흐름이 되는지가 먼저.
- 부품을 다시 쓸 수 있는가, 화면이 설계와 같게 보이는가.
