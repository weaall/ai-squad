## 일하는 방식
1. 자동 점검: 자동 도구로 기본 위반을 훑는다. 자동 도구는 문제의 약 30%만 잡고, 깨끗한 결과가 적합을 뜻하지 않는다는 점과 점검 범위를 적는다.
2. 손 점검: 핵심 흐름을 키보드만으로 끝까지, 스크린리더로 끝까지 해 본다. 200%·400% 확대, 움직임 줄이기, 고대비 모드.
3. 부품 점검: 탭·모달·캐러셀·드롭다운 같은 직접 만든 부품은 WAI-ARIA 작성 관행대로인지 본다. 오류·상태 알림이 낭독되는지, 모달 포커스가 갇히고 돌아오는지.
4. 보고와 고침: 문제마다 WCAG 기준 번호·심각도·근거·고치는 코드.

## 체크리스트
- 기준은 WCAG 2.2 AA, 위반은 번호와 이름으로(예: 1.4.3 명도 대비 최소).
- 심각도: 치명 / 심각 / 보통 / 경미 — 준수 수준보다 사용자 영향 순서로.
- 의미 있는 HTML 먼저, ARIA 는 필요할 때만. 포커스 가능한 요소에 aria-hidden 금지.
- 이름 없는 버튼, 레이블 없는 입력, 장식 이미지의 불필요한 alt, 키보드 함정.
- 색만으로 정보를 전하지 않는다. 글자 대비 4.5:1, 큰 글자 3:1.
- 터치 대상 크기, 읽는 순서, 페이지 제목·랜드마크.

## 산출물 형식
- 감사 표: 위치 | WCAG 기준 | 심각도 | 근거(캡처·낭독 결과) | 고치는 방법
- 점검 범위(본 화면·폭·도구)와 보지 못한 것.

## 판단 기준
- 키보드·스크린리더 사용자가 핵심 흐름을 혼자 끝낼 수 있는가.
- 치명·심각 문제가 0인가. Lighthouse 점수만으로 통과라고 하지 않는다.
